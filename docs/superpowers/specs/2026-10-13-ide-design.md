# Furnica IDE: design

Date: 2026-10-13. Status: approved in conversation, awaiting review of this document.

## Goal

A web IDE for the Furnica (ant) language that brings the four packages together: write a program, set up the 10 × 10 grid, run it with an animated ant, open and save the original `.ant` files, and solve the 24 tasks of the "Sarcina Furnica" worksheet.

### Audience

A mix, in this order of priority:

1. **Students and teachers.** Tasks come first and the interface stays simple. The UI defaults to Romanian.
2. **People who know the original program.** The IDE keeps the original's keyword-insert buttons, grid controls (character, delete, arrows, rotate), ant sprites and speed scale. It does not copy the Delphi menus or dialogs.
3. **Developers.** The layout is clean and modern.

### Success criteria

- Every task solution in `packages/ant-tasks/solutions/` can be pasted into its task, run, and is reported as solved.
- The `.ant` fixtures of `packages/ant-file` open and save back byte for byte.
- Work survives a page reload.
- Login and cloud storage can be added later without changing the UI (see [Later](#later)).

## Concepts

- **Task:** a fixed problem from `@repo/ant-tasks`: a number (1–24), the start world `START` and a goal layout. Tasks are read-only, built into the app and the same for everyone.
- **Exercise:** a user's saved work: a title, a language, a program, a start world, an optional `taskNumber` and whether it was solved.
  - **Task exercise:** an exercise with a `taskNumber`. It starts from the task's start world and is checked against the task's goal after each run.
  - **Free exercise:** an exercise without a `taskNumber`. It has no goal and is never "solved".
  - There is at most one exercise per task.

## Architecture

The app is a Next.js (App Router) application in a new `apps/ide` workspace package. The IDE itself runs entirely in the browser. Version 1 has no server code, but the App Router leaves room for API routes and authentication later.

```
apps/ide/                       created by create-next-app (defaults: no src/ directory)
  app/
    layout.tsx                  html, theme, i18n and store providers
    globals.css                 Tailwind and theme tokens (from create-next-app and shadcn init)
    page.tsx                    start page: tasks, free program, saved exercises
    ide/page.tsx                the IDE; loads <Ide> with ssr: false
  ide/
    Ide.tsx                     layout: editor | grid and controls | task panel
    state.ts                    IdeState, actions, reducer
    editor/                     Monaco wrapper, theme, tokens, markers, current-line decoration
    grid/                       10 × 10 view, cell editing, ant sprite
    run/                        useRunLoop: steps a Run on a timer
    tasks/                      goal view and goal check
    files/                      open and save .ant files
    keywords/                   keyword-insert buttons
  storage/
    ExerciseStore.ts            interface and types
    IndexedDbExerciseStore.ts   version 1 implementation
    MemoryExerciseStore.ts      fallback when IndexedDB is unavailable
    StoreProvider.tsx
  i18n/                         ro, en and ru UI messages
  components/ui/                shadcn/ui components (generated by shadcn add)
  lib/utils.ts                  cn() (generated by shadcn init)
  public/sprites/               ant sprites, one per facing
  components.json               shadcn/ui configuration (generated by shadcn init)
```

### Dependencies

- **Workspace packages:** `@repo/ant-grammar`, `@repo/ant-runtime`, `@repo/ant-file` and `@repo/ant-tasks` as `workspace:*`. They export TypeScript source, so `next.config.ts` lists them in `transpilePackages`.
- **Editor:** `monaco-editor`, loaded through `@monaco-editor/react` configured to use the local `monaco-editor` package rather than the CDN.
- **Styling and components:** Tailwind CSS v4 (through `@tailwindcss/postcss`), shadcn/ui, `next-themes` for light and dark mode, and `sonner` for toasts.
- **Storage:** `idb`.
- **Tests:** Vitest, Testing Library (jsdom), `fake-indexeddb`, Playwright.

`pnpm-workspace.yaml` adds `apps/*`.

### Project setup

Every tool is added with its official installer or guide, run from the repository, and the generated files are kept as generated except where noted. In order:

1. **Workspace.** Add `apps/*` to `pnpm-workspace.yaml`.
2. **Next.js, TypeScript, Tailwind CSS v4, ESLint.** Run `pnpm create next-app@latest apps/ide --yes` ([Next.js installation](https://nextjs.org/docs/app/getting-started/installation)). The recommended defaults include TypeScript, ESLint, Tailwind CSS (with `@tailwindcss/postcss` and `@import "tailwindcss"`), the App Router, Turbopack, the `@/*` alias and `AGENTS.md`. Tailwind therefore needs no separate installation.
3. **shadcn/ui.** In `apps/ide`, run `pnpm dlx shadcn@latest init`. This is the "existing Next.js project" path of the [shadcn/ui Next.js guide](https://ui.shadcn.com/docs/installation/next). Then add components with `pnpm dlx shadcn@latest add <component>`. The `--monorepo` mode is not used: it creates a shared `packages/ui` and Turborepo, which one app does not need.
4. **Vitest and Testing Library.** Follow the [Next.js Vitest guide](https://nextjs.org/docs/app/guides/testing/vitest): `pnpm add -D vitest @vitejs/plugin-react jsdom @testing-library/react @testing-library/dom vite-tsconfig-paths`, and its `vitest.config.mts`. The app's test script is `vitest run`, the same as the packages.
5. **Playwright.** Follow the [Next.js Playwright guide](https://nextjs.org/docs/app/guides/testing/playwright): `pnpm create playwright`, with only Chromium configured and `webServer` set to start the app.
6. **Monaco, `idb`, `next-themes`.** Install them with `pnpm add`. Configure `@monaco-editor/react` to use the local `monaco-editor` package, following its README.

After each step, the generated changes are committed separately, so the app's own code stays apart from the scaffolding.

### Changes to existing packages

The ant's moves are private to `Run` in `@repo/ant-runtime`. The grid's arrow buttons need the same rules, including pushing. So the move logic moves into a pure, exported function in `world.ts`:

```ts
export type MoveResult =
	| { ok: true; world: World; push?: Push }
	| { ok: false; world: World; error: "wall" | "push-off-grid" | "push-blocked" };

export function moveAnt(world: World, direction: Direction): MoveResult;
```

On failure, `world` holds the ant turned to the direction but not moved, matching the runtime. `Run` then uses `moveAnt`, and the existing runtime tests guard the refactor. `Direction` is exported too.

## User interface

### Layout

```
┌ toolbar: New · Open · Save │ Check · Run · Step · Stop · Reset │ speed │ language │ theme ┐
├──────────────────────────────┬──────────────────────────┬──────────────────┤
│ keyword buttons              │  10 × 10 grid            │ Task N           │
│ Monaco editor                │  coordinates 1..10       │ goal (mini grid) │
│                              │  character · delete      │ status           │
│                              │  arrows · rotate         │                  │
├──────────────────────────────┴──────────────────────────┴──────────────────┤
│ status bar: syntax OK / error on line N · step count · run state            │
└─────────────────────────────────────────────────────────────────────────────┘
```

On narrow screens the panels stack, and the editor and grid share tabs. A free exercise shows no task panel.

### Modes

- **Setup** (default):
  - Clicking an empty cell places the current character. The character box takes one grapheme and refuses empty, blank and `*`.
  - With "delete" on, a click clears the cell instead.
  - The ant's cell cannot be edited.
  - The arrow buttons move the ant with `moveAnt`. A failed move shows a toast and still turns the ant.
  - "Rotate" cycles the facing counter-clockwise: right, up, left, down (spec §10).
  - All of these change the start world.
- **Running and paused:**
  - The editor is read-only and the grid cannot be edited.
  - The range of the step being run is highlighted in the editor.
- **Done:** the run finished, failed or was stopped. Editing either the program or the grid returns to setup, starting from the start world.

### Actions

- **Check:** parses the program and shows its diagnostics as Monaco markers, with a message in the status bar.
- **Run:**
  - Parses first. If there are diagnostics, it shows them and does not run.
  - Otherwise it keeps the start world as a snapshot and animates the run to its end.
- **Step:** runs one step from setup or paused, starting a paused run if none exists.
- **Stop:** ends the run. The grid keeps the world where it stopped.
- **Reset:** puts the start world back on the grid and returns to setup.
- **Speed:** a slider over the original's scale, positions 0 to 20, with a delay of `200 − 10 · position` ms. The default is position 10 (100 ms). The setting is kept in `localStorage`.
- **New:** asks for confirmation, then creates a free exercise with the default world (`INITIAL_WORLD`).

### Language

One switch (ro, en, ru) sets the UI language, the keyword language used for highlighting and parsing, and the keyword buttons. The default is Romanian. Switching while the program is not empty asks for confirmation, since the program's keywords will no longer match. Translating programs between languages is out of scope.

### Keyword buttons

These follow spec §10:
- BEGIN and END insert a new line before the caret line.
- Every other keyword appends the keyword and a space to the end of the caret line. Unlike the original, a space is added before it when the line ends in a word.
- DO appends without the space.
- "END..." appends END and a space.

The spellings come from `KEYWORD_SETS[language]`.

### Files

- **Open:**
  - Opens a `.ant` file (world and program) or a `.antp` file (program only).
  - The encoding is windows-1251 for Russian and windows-1250 otherwise. A selector in the open dialog can override it.
  - Opening replaces the current exercise's program and start world after a confirmation.
- **Save:**
  - Downloads a `.ant` file with the start world and the program, in the same default encoding.
  - If a character cannot be written in that encoding, a dialog names the character and offers "Save as UTF-8" or "Cancel".

### Tasks

- The task panel shows the goal as a mini grid.
- After every run of a task exercise, `checkGoal` compares the grid with the goal, ignoring the ant.
- The panel shows "Solved", or lists the missing and misplaced letters and highlights their cells on the grid.
- A solved run marks the exercise as solved, and it stays solved.

## State and data flow

The IDE state is one `useReducer` held in a React context. No state library.

```ts
type Mode = "setup" | "running" | "paused" | "done";

interface IdeState {
	exercise: Exercise;          // id, title, language, source, start, taskNumber, solved
	world: World;                // what the grid shows
	mode: Mode;
	run?: {
		steps: number;
		current?: Range;           // range of the step being run
		error?: RuntimeError;
		status: RunStatus;
	};
	diagnostics: readonly Diagnostic[];
	goalCheck?: GoalCheck;
	speed: number;               // 0..20
}
```

- **The run.** The mutable `Run` object lives in a `useRef`, not in the state.
  - `useRunLoop` schedules `run.step()` with the current delay and dispatches each step with the run's world.
  - At delay 0 it runs a batch of steps per animation frame, so runs that reach the 100,000-step limit do not freeze the page.
  - Stop and unmount clear the timer.
- **Editing the program.** Each change updates `exercise.source`. A debounced (300 ms) `parse` updates `diagnostics`, which become Monaco markers.
- **Editing the grid.** Grid edits are pure functions over `World`: place a character, clear a cell, `moveAnt`, rotate.
- **Saving.** Every change to the exercise is saved to the store, debounced by 500 ms, and once more when the page is hidden.

## Storage

```ts
interface Exercise {
	readonly id: string;
	readonly title: string;
	readonly language: Language;
	readonly source: string;
	readonly start: World;
	readonly taskNumber?: number;
	readonly solved: boolean;
	readonly updatedAt: number;
}

type ExerciseSummary = Pick<Exercise, "id" | "title" | "taskNumber" | "solved" | "updatedAt">;

interface ExerciseStore {
	list(): Promise<ExerciseSummary[]>;
	load(id: string): Promise<Exercise | undefined>;
	findByTask(taskNumber: number): Promise<Exercise | undefined>;
	save(exercise: Exercise): Promise<void>;
	remove(id: string): Promise<void>;
}
```

- **Implementations.** Version 1 provides `IndexedDbExerciseStore` and, when IndexedDB is unavailable, `MemoryExerciseStore`. With the fallback, a banner says that work is not being saved.
- **Injection.** `StoreProvider` passes the store to the app, so a cloud store can replace it without changes to the UI.

### Routes

- **`/`** is the start page. It lists:
  - the 24 tasks, with a check mark on solved ones;
  - "Free program";
  - the saved free exercises, with delete.
- **`/ide?task=N`** opens the exercise for task N, creating it from `START` if there is none.
- **`/ide?id=…`** opens a saved exercise.
- **`/ide`** with no query creates a free exercise and replaces the URL with its id.

## Errors

| Situation | Behaviour |
|---|---|
| Syntax errors | Monaco markers and a status bar message, from `formatMessage`. Run is blocked. |
| Runtime error | Marker on the failing statement and a toast. The grid keeps the world at the failure. `step-limit` and `depth-limit` get their own explanations. |
| `AntFileError` on open | Dialog with the error's "Line N: …" message. The exercise is unchanged. |
| Character not in the save encoding | Dialog naming the character, offering UTF-8. |
| IndexedDB unavailable | Memory store and a banner. |
| Monaco fails to load | Error boundary with a retry button. |

UI messages are translated by the IDE. Diagnostics and runtime errors are translated by their `code`, and English falls back to `formatMessage`.

## Testing

- **Unit (Vitest):**
  - the reducer;
  - the grid edits;
  - `moveAnt` in `@repo/ant-runtime`;
  - `useRunLoop` with fake timers;
  - `IndexedDbExerciseStore` with `fake-indexeddb`;
  - the keyword-insert rules.
- **Components (Vitest, Testing Library, jsdom):**
  - the grid: placing, deleting, the protected ant cell;
  - which toolbar buttons are enabled in each mode;
  - the task panel.
  - Monaco is mocked in these tests.
- **End to end (Playwright, Chromium):**
  1. Open task 1, enter `sarcina-01.antp`, run it, and see "Solved".
  2. Open each `ant-file` fixture, save it, and compare the downloaded bytes with the original.
  3. A syntax error shows a marker and blocks Run.
- **Scripts:** `pnpm --filter ide dev | build | test | e2e | typecheck`.

## Open technical checks

These are resolved at the start of the implementation plan:

- **TypeScript 7.** Whether Next.js type-checks with the repository's TypeScript 7. If not, the app pins TypeScript 5 for itself.
- **Prettier and ESLint.** The repository formats with Prettier, and create-next-app adds ESLint. ESLint is kept for lint rules only, and the generated files are reformatted by the existing lint-staged Prettier hook.
- **`minimumReleaseAge`.** The workspace refuses packages published less than a day ago. If a `@latest` installer picks one, the previous version is used.
- **Sprite transparency.** The sprites are `evidence/images/{sus,jos,stinga,dreapta}.png`, and the original made their bottom-left colour transparent. The copies in `public/sprites/` are made transparent the same way, once, with a small script kept in the app.

## Out of scope for version 1

- login and cloud storage;
- translating programs between languages;
- shareable links;
- continuous integration;
- deployment.

## Later

- **Login.** An authentication provider (Auth.js, Clerk or Supabase Auth) with Next.js middleware. The current user comes from a context that is anonymous in version 1.
- **Cloud storage.** A `CloudExerciseStore` over API routes in `app/api/exercises`, implementing `ExerciseStore` and keyed by user. IndexedDB remains as an offline cache that syncs when online.
- **Deployment.** On Vercel.
